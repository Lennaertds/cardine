## Went wrong

- The diagnosis first went the wrong way. Two probe fixtures lived under `/tmp`, which the cage replaces, so they never ran; and a probe without `cd` reported `sys.prefix=/home/ventje/.venv`, which read as a smoking gun for a host venv. **Set the fixture up inside a bound workspace, `cd` into it explicitly, and confirm the probe ran (`PROBE-RAN`) before trusting any output.**
- Probe fixtures were created under the workspace and masked, so their files became mounts that `rm -rf` from inside the cage cannot remove (no `CAP_SYS_ADMIN` in the userns). Same trap the fix removes, now visible: keep throwaway projects outside the bound roots, or clean up before the cage dies.
- The first `--chdir "$PWD"` made the cage fail with `bwrap: Can't chdir` whenever the caller's cwd was not bound — DSH itself binds the repo, but the gate ran from another dir. The existing `check-bwrap-secrets.sh` caught it in one run. Defaults that look harmless ("start where the caller is") need a fallback for the case that used to work silently.
- A `find -path` pattern with `(...|...)` never matched here (`find (GNU findutils) 4.11.0-modified`). Name-based `-prune` build from an array is what works; do not copy GNU-regex `find -path` idioms into `cardine-bwrap` without testing them on this machine.
- Editing the running shell's own `cardine-bwrap` is brittle: every `bash` call goes through that file, so a half-written edit turned the whole tool surface into "no sandbox backend is usable". Write the file atomically (temp file + `mv`) when the change is in the runner itself.
