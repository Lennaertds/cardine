## Went wrong

- A thread started from a folder outside the project root gets no cage at all: every command failed with `spawn …/cardine-bwrap ENOENT`, while `grep`/`glob` kept working because they do not use the runner. The lab is fine; the cwd was the parent (`Cardine/`, which is not a git root). Start a session inside the project the profile names.
- The installer block was `source`d to dry-run it, so it installed really: a Python 3.13 and jarvis-mcp were downloaded. Nothing reached the host (uv's cache and `~/.local/share` live in the per-call tmpfs of the cage); the scratch HOME under `tmp/` is gone. Lesson: an installer never has a dry-run mode; stub the external tools (`uv`, `jarvis`) instead of running it.
- `pkill -f 'lab-test-home'` killed the agent's own shell twice, because `-f` matches the command line of the shell that runs it. The same trap probably explains the missing `~/.local/bin/jarvis` on the host ("pkill -9 -f /.local/bin/dsh"). Lesson: never `pkill -f`; kill by PID after reading `/proc/<pid>/cmdline`, or use `dsh kill`.
- `cardine-move --fix` failed against a profile whose new root sat inside the old one: the check grepped the old path as a substring of the new one. It now compares the roots, not substrings.
- `cardine-status.sh --fix` repaired only the runner and the slice-check, and only in `~/.dsh`; `workspaceRoot`, `mcp-jarvis.cwd` and `DSH_HOME` were ignored. That is why the move script owns the full rewrite.
